## 1. ProofBerry AI / PAAOS

### Customer Truth
The landing flow initializes the Candidate surface when no audience is supplied. Before RUN141, `waitlist_form_start` wrote `audience=candidate` from that default UI state even if the visitor had not explicitly selected Candidate and had not arrived through a deliberate candidate audience URL. A default tab is not candidate intent, and using it as candidate funnel attribution can overstate qualified candidate starts.

### Creative Strategy
- **PB-TXT-151 — “A default tab is not candidate intent. Start with one claim worth proving.”**
- **PB-DOC-057 — One-Claim Proof Starter**

The candidate offer remains evidence-first: choose one target role, one capability claim, deliberately review the evidence already available, treat missing evidence as a build list, and request early access only if the proof-building workflow is useful.

### Production Readiness
Base44 source `src/components/landing/WaitlistSection.jsx` now sets `waitlist_form_start.audience` only after either explicit audience selection or a deliberate audience URL. Metadata also records whether the audience was explicitly selected.

## 2. KAMERON AI OS

### Customer Truth
The bounded recovery request initialized `decision_window` to `30_days`, while the UI `scopeReady` condition did not require a deliberate timing selection. A technically detailed form could therefore look like 30-day commercial intent even when the buyer never selected a timeline.

### Creative Strategy
- **KAM-TXT-004 — “Choose the decision window before the recovery test counts as qualified.”**
- **KAM-DOC-004 — Deliberate Recovery Timing Card**

A recovery evaluation should define the failure to exercise, the state-consistency and no-duplicate receipts, the human resume authority, the available runtime/integration boundary, and the buyer’s deliberate evaluation window before contact.

### Production Readiness
Base44 `src/pages/Pricing.jsx` now:
- initializes `decision_window` blank;
- requires `pilot.decision_window` for `scopeReady`;
- makes the timing selector required with a neutral “Choose evaluation timing” placeholder;
- keeps contact hidden until a deliberate evaluation window is selected;
- links KAM-DOC-004 from the bounded recovery pilot section.

Static asset created: `public/marketing/KAM-DOC-004-deliberate-recovery-timing-card.html`.

## 3. CityVerse Live

### Customer Truth
The first-test funnel already required an explicit experience, success signal, evidence receipt category, dependency, and decision window. However, anonymous `CityVerseScopeSignal` telemetry could still be contaminated by internal/preview interactions and repeated brief-copy/review clicks from the same browser session. The durable CityVerseInterest schema also did not require `decision_window` even though the UI did.

### Creative Strategy
- **CV-TXT-008 — “Define one first test, then count the decision—not repeated clicks.”**
- **CV-DOC-004 — One Test, One Signal**

The commercial signal should represent one deliberately scoped experience, one success signal, one evidence/receipt category, one dependency, and one explicit evaluation window—not repeated button activity.

### Production Readiness
`CityVerseScopeSignal` now includes:
- anonymous `session_id`;
- `environment` (`production`, `preview`, `unknown`);
- `measurement_eligible` boolean.

The live first-test flow now:
- excludes localhost/preview runtime from qualified scope-signal creation;
- deduplicates `brief_copy` and `review_request_click` once per anonymous browser session/action type;
- writes `environment=production` and `measurement_eligible=true` only in the production path;
- advances default creative attribution from CV-TXT-007 to CV-TXT-008;
- requires `CityVerseInterest.decision_window` at the durable schema level;
- links CV-DOC-004 from the first-test page.

Static asset created: `public/marketing/CV-DOC-004-one-test-one-signal-card.html`.
