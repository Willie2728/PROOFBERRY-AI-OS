## PB-DOC-020 — Pilot Readiness Gate

**Hook:** A pilot needs a readiness gate — not just a start date.

**CTA:** Bring one active requisition and the people who own the decision.

The static card qualifies staffing design-partner candidates before a pilot begins. It requires:
- one active requisition with clear must-haves;
- one staffing-side owner;
- one client-side reviewer;
- the current submission workflow kept as the baseline;
- an agreed expand / revise / stop decision.

The card is an illustrative early-access pilot method. It does not promise outcomes.

## PB-TXT-043 — Buyer qualification post

The fastest way to waste an AI pilot is to start before the buyer is ready to evaluate it.

For a ProofBerry staffing design-partner conversation, five conditions should be true before the pilot begins: one active requisition with clear must-haves; one staffing-side owner; one client-side reviewer; the current submission workflow retained as a baseline; and an agreed expand / revise / stop decision at the end.

If any one is missing, fix the readiness gap first.

If all five are present, you have a test that can produce useful evidence instead of another vague AI trial.

ProofBerry's role is to help make the candidate-evidence handoff more inspectable while the consequential hiring decision remains human-owned.

**CTA:** If you have one active requisition, one staffing owner, one client reviewer, a baseline workflow, and an agreed stop/expand decision, use that role for the design-partner discussion.
