# RUN131 — Scope-ready vs evaluation-ready

## Customer Truth
A buyer can have a real role, accountable owner, decision window, and success rule while still lacking the four evaluation-quality boundaries needed to interpret a one-role test. Those are two different commercial states and should not be labeled with the same CTA.

## Deployable copy
**Hook:** Scope-ready and evaluation-ready are different buyer states.

**Body:** If the live role, human owner, decision window, and success rule are defined but the baseline, evidence-delivery boundary, evidence-retention boundary, or minimum evidence rule is still incomplete, ask for a **scoping review**. When all four evaluation-quality boundaries are defined, ask for an **evaluation review**. Preserve the buyer state instead of making one click imply more readiness than the buyer actually declared.

**CTA:** Request a scoping review when evaluation design is incomplete; request an evaluation review only when the four evaluation-quality boundaries are defined.

## Claims boundary
This wording describes buyer-provided planning state only. It does not accept or schedule a pilot, verify authority or budget, verify candidates, establish compliance, prove product performance, create a hiring outcome, or establish conversion lift.
