# RUN109 — Valore AI Security Sentinel — Prototype Truth Before Pilot

## Customer Truth
A museum, collector, insurer, conservator, or investor should not have to guess which Sentinel claims are proven. A deep-tech security concept becomes more credible when the buyer can define one threat, one artifact context, and one receipt that must be demonstrated before a technical review advances.

## Creative Strategy
**Asset:** VAL-SENT-TXT-001 — Make One Artwork Earn the Prototype Test

**Hook:** Before you call it protection, define the receipt that would prove the test.

**CTA:** Build the One-Artifact Threat Brief before sharing contact information.

## Production Readiness
RUN109 changed the active Base44 application from assertive product language to a prototype/validation posture.

- Hero now labels the system as a prototype architecture and treats thickness, satellite link, and tamper detection as design/test targets rather than proven attributes.
- Problem section removes unsupported theft/recovery statistics and instead frames the buyer's evidence questions: movement, tamper, telemetry/failure modes, and conservation approval.
- Solution section labels low-visibility attachment, off-grid telemetry, edge event logic, and tamper evidence as prototype goals that require testing.
- How It Works now begins on a sacrificial or conservator-approved test surface, measures baseline/false positives, verifies event receipts, and measures alert handoff rather than promising instant global alerts.
- Investment copy now labels the $90K prototype and $1.2M seed figures as planning estimates/targets rather than completed financing, delivered MVP, certification, or insurance sales.
- The previous client-only email form falsely displayed a success state without durable persistence. It was replaced by a no-contact One-Artifact Threat Brief. A buyer defines artifact context, primary threat, decision window, and the evidence required before technical review. Email appears only after explicit review intent.

New Base44 entities:
- `SentinelScopeSignal`: privacy-minimized structured `brief_copy` / `review_request_click` intent.
- `SentinelPilotRequest`: durable review request containing email, structured context/threat/window, buyer-defined proof requirement, attribution, timestamp, and internal status.

The success state now states only that the request was recorded for evaluation; it does not imply pilot acceptance, deployment, response time, conservation approval, certification, theft prevention, recovery performance, or commercial terms.
