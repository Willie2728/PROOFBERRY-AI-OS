# Wilkerson Collective Autonomous Agent Operating Standard

Status: ACTIVE until explicitly revoked by the owner.

## Mandatory rules
Every autonomous workflow must have a named agent, a human-readable Wilkerson Collective Agent ID, a durable registry record, a defined purpose and intentions, past/current/next workflow state, status, system location, output location, and activity history.

Every delegated build or tool-driven workflow must have a liaison/monitor agent. The liaison is responsible for watching for clarification questions, approval prompts, errors, stalls, dependency failures, and completion events; escalating required actions; and verifying the endpoint before work is marked complete.

Marketing, research, optimization, and stack-review agents are standing operational roles. They are expected to continuously identify improvements, create and organize deployable content, maintain reusable winning recipes, and keep a ready-to-deploy content inventory across Wilkerson Collective products.

The content system must maintain durable folders or records by product, audience, channel, format, funnel stage, version, status, performance, and source. When a content area grows large, it must be subdivided and organized rather than allowed to become unstructured.

GitHub is the durable source of truth for code, operating standards, product documentation, scripts, and metadata. Base44 may host the application UI, agent definitions, entities, workflows, and Command Center. Persistent external execution environments such as Orgo/OpenClaw are intended for always-on workers when connected and available. Render is used for deployment where applicable.

No agent may claim a render, publication, deployment, customer result, metric, or completion state without verifiable evidence. Unsupported marketing claims, fabricated testimonials, deceptive urgency, privacy violations, or false status reporting are prohibited.
